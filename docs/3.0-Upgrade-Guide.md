# Updating to 3.0

## Breaking Changes

### Storage Paths Are Now Strongly Typed

Storage path parameters (`objectName`, `newName`, etc.) across `IObjectStorage`
and `ISignedUrlObjectStorage` now use a `StoragePath` type instead of `string`.
`StoragePath` has implicit conversions to and from `string`, so most existing
calling code will continue to compile without changes:

```csharp
await storage.WriteAsync("myfolder/file.txt", stream);
```

If you have a custom `IObjectStorage` implementation, you'll need to update
its method signatures to use `StoragePath` instead of `string`.

### `ListAsync` Results Are Normalized

Paths returned from `ListAsync` are now normalized to include a leading `/`,
for consistency with paths used elsewhere in the library. Previously, some
providers returned paths in their native format (for example, without a
leading slash). This should only affect you if you are comparing `ListAsync`
results directly against unnormalized path strings.

### `IObjectStorage.RenameAsync`

`IObjectStorage` now has a `RenameAsync` method. This should only affect you
if you have a custom `IObjectStorage` implementation, since you'll need to
add an implementation of this method.

## New Features

### Rename Support

All built-in providers now implement `RenameAsync`, so you can rename a
stored object without having to manually copy and delete it:

```csharp
await storage.RenameAsync("myfolder/file.txt", "myfolder/renamed.txt");
```

### `StoragePath` Properties

`StoragePath` now exposes `Name`, `Folder`, `IsFolder`, and `IsFile`
properties, making it easier to work with parts of a path without manual
string parsing:

```csharp
StoragePath path = "myfolder/file.txt";

var name = path.Name;     // "file.txt"
var folder = path.Folder; // "/myfolder/"
```

`StoragePath.Split` is also now public, alongside the existing
`StoragePath.Normalize`, for use when implementing your own storage
provider.

### .NET Standard 2.0 Target

Packages now also target `netstandard2.0`, in addition to `net6.0` and
`net8.0`, widening the set of projects that can consume them.

### SourceLink for Provider Packages

SourceLink, previously only enabled for the main `Centeva.ObjectStorage`
package, is now enabled for the AWS, Azure Blob, and Google Cloud provider
packages as well, so you can step into their source code when debugging.
