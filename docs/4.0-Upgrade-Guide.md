# Updating to 4.0

## Breaking Changes

### `ListAsync` Returns `StorageEntry` Objects and Supports Folder Paths

`ListAsync` no longer returns a flat `IReadOnlyCollection<string>` of every
object name in the store. It now returns `IReadOnlyCollection<StorageEntry>`,
takes an optional `StoragePath` to list within (defaulting to the root), and
an optional `recurse` flag:

```csharp
Task<IReadOnlyCollection<StorageEntry>> ListAsync(
    StoragePath? path = null,
    bool recurse = false,
    CancellationToken cancellationToken = default);
```

By default, `ListAsync` only returns the entries directly within the given
path (including "folder" entries, whose path ends in `/`), instead of
recursively returning every object in the store. Pass `recurse: true` to get
the old flattened behavior, or call it with a specific folder path to list
just that folder. Passing a path that isn't a folder (i.e. doesn't end in
`/`) throws an `ArgumentException`.

You'll need to update any code that consumes `ListAsync` to work with
`StorageEntry` (which exposes `Path`, `Name`, `CreationTime`,
`LastModificationTime`, and `SizeInBytes`) instead of a plain string, and to
pass `recurse: true` if you relied on getting every object back in one call.

### `WriteAsync` No Longer Accepts a `contentType` Parameter

The `contentType` parameter has been removed from `WriteAsync`, since not all
providers supported it:

```csharp
Task WriteAsync(StoragePath path, Stream contentStream, CancellationToken cancellationToken = default);
```

This should only affect you if you were passing a `contentType` argument.
Remove it from your calls; if you were relying on the content type being set
on the stored object, you'll need to set it through provider-specific means.

### `IObjectStorage` Implementers Must Add `GetAsync`

`IObjectStorage` has a new `GetAsync(StoragePath, CancellationToken)` method
that returns a `StorageEntry?` with metadata about the object at a given
path, or `null` if it doesn't exist. This should only affect you if you have
your own custom implementation of `IObjectStorage`, since the built-in
providers already implement it.

## New Features

### `GetAsync` for Object Metadata

All built-in providers now support `GetAsync`, which retrieves metadata
(creation time, last modification time, size) for a stored object without
downloading its contents:

```csharp
StorageEntry? entry = await storage.GetAsync("/path/to/file.txt");
```

The Disk provider is the only one that will also return metadata for
folders, since the cloud providers don't have a real concept of folders.

### `StoragePath` Equality and `ToString()`

`StoragePath` now implements `IEquatable<StoragePath>`, with matching
`Equals` and `GetHashCode` overrides, so two `StoragePath` instances with the
same normalized path compare equal. It also has a `ToString()` override that
returns the full path.
