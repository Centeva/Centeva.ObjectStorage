# Updating to 7.1.0

## Breaking Changes

### Connection String URL-Decoding

Connection string parameter values are now URL-decoded with
`Uri.UnescapeDataString` instead of `HttpUtility.UrlDecode`.  The old method
treated a literal `+` as a space (HTML form-encoding behavior), which could
corrupt Base64 values -- such as Azure account keys -- containing a `+`
character; this also removes the `Replace(' ', '+')` workaround previously
applied in the Azure connection factories to compensate.  This should only
affect you if a connection string value you supply relies on `+` being
decoded as a space.

The `StringExtensions` class (`Base64Decode`/`UrlDecode`) has been removed as
part of this change.  This should only affect you if you were calling those
methods directly.

### `StorageFactory.GetConnection` renamed to `CreateConnection`

`GetConnection` returns a new `IObjectStorage` instance on every call rather
than an existing one, so `CreateConnection` is a more accurate name and is
consistent with .NET conventions (e.g. `IHttpClientFactory.CreateClient`,
`IDbContextFactory.CreateDbContext`). `GetConnection` still works but is
marked as obsolete and will be removed in a future release.

## New Features

### Dependency Injection Registration

`IServiceCollection` extension methods are now available for registering
object storage with the built-in .NET dependency injection container. If
your application currently wires up `StorageFactory` manually, you can
replace code like this:

```csharp
builder.Services.AddSingleton(sp =>
    new StorageFactory()
        .UseAwsS3Storage()
        .CreateConnection(builder.Configuration.GetConnectionString("ObjectStorage")!));
```

with:

```csharp
builder.Services.AddObjectStorage(config => config
    .UseAwsS3Storage()
    .UseConnectionString(builder.Configuration.GetConnectionString("ObjectStorage")!));
```

`AddObjectStorage` registers an `IObjectStorage` singleton, along with any
optional capability interfaces the configured provider implements (such as
`ISupportsSignedUrls` and `ISupportsMetadata`), so those can be injected
directly without a cast.

If your application needs more than one storage configuration, register them
as keyed services with `AddKeyedObjectStorage`. If the connection string
isn't known until runtime -- for example, a multi-tenant application where
each tenant has its own storage configuration -- register an
`IObjectStorageFactory` instead with `AddObjectStorageFactory`, and resolve
connections from it by connection string on demand.

See the [Dependency Injection](../README.md#dependency-injection) section of
the README for full details and examples.
